# 模拟订单场景 v0.1

## 1. 目的

第一版准备 10 个模拟订单，用于：

- 本人订单查询测试
- 他人订单越权测试
- 不同订单状态测试
- 物流查询测试
- 售后预检查测试
- 异常场景测试

所有订单均为虚构数据。

当前文件只设计订单场景，不代表已经写入 MySQL。

## 2. 第一版订单场景

| 订单号 | 所属用户 | 订单状态 | 主要测试用途 |
|---|---|---|---|
| O1001 | customer_a | 已发货 | 正常本人订单查询 + 正常物流查询 |
| O1002 | customer_a | 已签收 | 已签收订单查询 + 售后预检查基础场景 |
| O1003 | customer_a | 已支付 | 已支付但尚未发货，无物流场景 |
| O1004 | customer_a | 已取消 | 取消订单场景 |
| O1005 | customer_a | 待支付 | 待支付订单场景 |
| O2001 | customer_b | 已发货 | customer_b 正常查询，同时用于 customer_a 越权测试 |
| O2002 | customer_b | 已签收 | customer_b 已签收订单 |
| O2003 | customer_b | 已支付 | 已支付但尚未发货场景 |
| O2004 | customer_b | 已取消 | 取消订单场景 |
| O2005 | customer_b | 已签收 | 后续设置为超过模拟售后规则期限的场景 |

## 3. 关键测试场景

### 场景 A：本人订单查询成功

登录用户：

customer_a

查询：

O1001

预期：

允许查询订单摘要。

### 场景 B：他人订单不可访问

登录用户：

customer_b

查询：

O1001

预期：

不返回订单内容。

统一返回：

未找到可访问的订单

### 场景 C：已支付但尚未发货

订单：

O1003

状态：

已支付

预期：

订单可以查询。

由于尚未发货，不应虚构物流单号或物流事件。

对用户说明：

尚未发货。

### 场景 D：取消订单

订单：

O1004

状态：

已取消

预期：

能够查询订单状态。

后续售后预检查时，应由后端根据订单状态和售后规则决定结果。

### 场景 E：刚签收订单

订单：

O1002

状态：

已签收

后续初始化数据时：

将 delivered_at 设置为接近当前模拟测试时间。

用途：

测试刚签收订单的售后预检查。

### 场景 F：超过模拟售后规则期限

订单：

O2005

状态：

已签收

后续初始化数据时：

根据最终确定的模拟售后规则，将 delivered_at 设置为超过对应规则允许期限。

用途：

测试售后规则的时间边界。
